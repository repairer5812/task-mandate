# Task Mandate 프로토콜
이 문서는 docs/SPEC.md의 번역본이다. 두 문서가 다르면 영어 원문이 맞다.

## 1. 소개

Task Mandate를 사용하면 한 사람이 한 사이트의 과업 하나를 에이전트 키 하나에 위임할 수 있다. 위임장으로 에이전트의 행동 시간과 횟수를 제한할 수 있다. 에이전트는 요청마다 서명한다. 사이트는 미리 설정한 키와 상태 저장소로 위임장과 요청을 직접 검증하며 이 과정에서 발급자에게 연락하지 않는다.

이 프로필은 SD-JWT VC, Web Bot Auth 태그가 붙은 RFC 9421 HTTP 메시지 서명, Ed25519를 사용한다. 0.1 버전은 연구용 실험 버전이다. 실제 신원 등록, 결제, 범용 브라우저 자동화, 온라인 철회는 이 프로필에서 다루지 않는다. 데모 앱은 [DEMO.md](DEMO.md)를 참고한다.

## 2. 용어

| 용어 | 뜻 |
| --- | --- |
| 본인 | 과업을 위임하는 사람이다. 본인의 키로 위임장에 서명한다. |
| 에이전트 | 위임장에 지정된 개인 키를 가진 호출자다. |
| 사이트 | HTTP 또는 HTTPS 오리진 하나에 있는 검증기와 애플리케이션이다. |
| 위임장 | 과업, 대상, 에이전트 키를 묶어 서명한 자격 증명이다. |
| 과업 | 유형으로 명시하는 작업이다. 리소스와 매개변수는 생략할 수 있다. |
| 조각 | 과업의 일정 구간에 적용하는 위임장 하나다. 갱신할 때는 같은 과업의 새 조각을 발급한다. |
| 사람 보증서 | 사이트별 주체 식별자를 본인 키에 연결하는 JWT다. 설정된 발급자가 발급한다. |
| 저장소 | 만료되지 않은 nonce, 행동 횟수, 사람 칸을 추적하는 데 쓰는 상태다. |

오리진은 HTTP 또는 HTTPS URL의 오리진을 직렬화한 값이다. 스킴과 호스트를 넣는다. 기본값이 아닌 포트를 쓰면 포트도 넣는다. 경로와 끝 슬래시는 넣지 않는다. 예를 들면 `https://court.example`이다. 설정한 오리진과 발급 시 넣은 대상은 처음부터 이 형식이어야 한다. 검증기는 두 값을 문자열로 비교한다.

공개 키 식별자는 RFC 7638에 따른 SHA-256 JWK 썸프린트를 패딩 없는 base64url로 인코딩한 값이다. Ed25519 공개 JWK는 `kty: "OKP"`, `crv: "Ed25519"`를 쓰고 `x`에는 유효한 공개 키를 넣는다. 발급자와 서명자는 그 공개 JWK에 대응하는 개인 JWK를 쓴다. 공개 키를 정규화할 때는 `kty`, `crv`, `x`만 남긴다.

## 3. 위임장 형식

`Agent-Mandate` 헤더에 컴팩트 형식의 SD-JWT VC를 넣어 보낸다. 이 프로필에서 그 값은 서명된 발급자 JWT 뒤에 `~`를 붙인 형태다. 모든 클레임은 발급자 JWT에 들어 있다. 검증기는 JWT를 검증한 뒤 페이로드를 그대로 쓴다. 공개 항목(disclosure)이나 SD-JWT 키 바인딩 JWT는 처리하지 않는다.

보호된 JOSE 헤더에는 `typ: "dc+sd-jwt"`, `alg: "EdDSA"`, 본인의 공개 `jwk`를 반드시 넣는다. 사이트는 이 키로 JWT를 검증한다. `iss` 값은 반드시 같은 키의 썸프린트와 일치한다.

| 클레임 | 유형 | 필수 여부 | 뜻 |
| --- | --- | --- | --- |
| `vct` | 문자열 | 필수 | 값은 정확히 `urn:task-mandate:v0`이다. |
| `iss` | 비어 있지 않은 문자열 | 필수 | `urn:jwk-thumbprint:sha-256:` 뒤에 본인 키의 썸프린트를 붙인 값이다. |
| `sub` | 비어 있지 않은 문자열 | 필수 | `pa`가 없으면 `iss`와 같다. `pa`가 있으면 보증받은 주체 식별자와 같다. |
| `aud` | 비어 있지 않은 문자열 | 필수 | 사이트의 오리진이다. 검증기에 설정된 오리진과 정확히 일치해야 한다. |
| `cnf` | 객체 | 필수 | 에이전트의 Ed25519 공개 JWK를 `jwk`에 담는다. |
| `task` | 객체 | 필수 | 비어 있지 않은 문자열 `type`을 담는다. 문자열 `resource`와 객체 `params`는 각각 생략할 수 있다. `resource`는 빈 문자열이어도 된다. 배열이나 null은 객체 검사를 통과하지 못한다. `params`의 의미는 애플리케이션이 정한다. |
| `limits` | 객체 | 선택 | 1 이상의 정수 `maxActions`를 담는다. |
| `iat` | 정수 | 필수 | 발급 시각을 Unix 초로 나타낸 값이다. |
| `nbf` | 정수 | 필수 | 조각의 시작 시각을 Unix 초로 나타낸 값이다. |
| `exp` | 정수 | 필수 | 조각의 만료 시각을 Unix 초로 나타낸 값이다. |
| `jti` | 비어 있지 않은 문자열 | 필수 | 조각 식별자다. 발급 도우미는 무작위 16바이트를 base64url로 인코딩해 만든다. |
| `tid` | 비어 있지 않은 문자열 | 선택 | 여러 조각이 같은 과업임을 나타내는 식별자다. 생략하면 검증기는 `jti`를 쓴다. |
| `tbeg` | 정수 | 조건부 | 과업의 시작 시각을 Unix 초로 나타낸 값이다. `onePerPerson`을 사용하고 `tid`가 있으면 필수다. 그 밖의 경우 `tbeg`가 없으면 검증기는 `iat`를 과업 시작 시각으로 쓴다. |
| `tend` | 정수 | 선택 | 과업의 종료 시각을 Unix 초로 나타낸 값이다. 생략하면 검증기는 `exp`를 쓴다. |
| `pa` | 문자열 | 조건부 | 컴팩트 형식의 사람 보증서 JWT다. 사이트가 `requirePerson`을 사용하면 필수다. |

검증기는 위임장 서명을 검증하기 전에 다음 크기 제한을 적용한다.

| 값 | 최댓값 |
| --- | --- |
| `Agent-Mandate` 헤더 값 | UTF-8 기준 8192바이트 |
| `pa` | UTF-8 기준 4096바이트 |
| `iss`, `sub` | 각각 256 UTF-16 코드 단위 |
| `jti`, `tid` | 각각 128 UTF-16 코드 단위 |

시각 값은 반드시 `iat <= exp`와 `nbf <= exp`를 만족한다. `tend`가 있으면 반드시 `exp <= tend`를 만족하고 `tbeg`가 있으면 반드시 `tbeg <= nbf`를 만족한다. `iat`와 `nbf` 사이의 순서는 검사하지 않는다. 크기가 제한값과 정확히 같으면 크기 검사를 통과한다.

`issueMandate`는 `principalKey`, `agentPublicKey`, `audience`, `task`, `durationSec`를 받는다. 기간은 1 이상 2592000 이하의 정수다. `now`의 기본값은 현재 시각이고 `notBefore`의 기본값은 발급 시각이다. 호출자가 지정한 `notBefore`, `taskBegin`, `taskEnd`는 유효한 날짜 값이어야 한다. 발급 도우미는 날짜 값을 Unix 초로 환산하고 소수점 이하는 버린다. 만료 시각은 `exp = nbf + durationSec`로 계산한다. 선택 인수 `taskId`, `taskBegin`, `taskEnd`는 각각 `tid`, `tbeg`, `tend`가 된다. 명시한 `taskEnd`가 `exp`보다 이르면 발급에 실패한다. 사이트는 발급 도우미의 검사와 별개로 전송된 값을 검증한다.

## 4. 사람 보증서

사람 보증서는 컴팩트 형식의 JWT다. 보호된 헤더에는 `typ: "person-attestation+jwt"`, `alg: "EdDSA"`, 사람 보증서 발급자 키의 썸프린트와 같은 `kid`를 반드시 넣는다. 검증기는 설정된 발급자 목록에서 키를 가져온다. 보증서에 들어 있는 키, 키 URL, 인증서 체인은 무시한다.

| 클레임 | 유형 | 뜻 |
| --- | --- | --- |
| `iss` | 비어 있지 않은 문자열 | 사람 보증서 발급자 식별자다. |
| `sub` | 비어 있지 않은 문자열 | 발급자와 대상 조합별 주체 식별자다. |
| `aud` | 문자열 | 사이트의 오리진이다. 사이트에 설정된 오리진과 정확히 일치해야 한다. |
| `cnf` | 객체 | 본인의 Ed25519 공개 JWK를 `jwk`에 담는다. |
| `iat` | 정수 | 발급 시각을 Unix 초로 나타낸 값이다. |
| `exp` | 정수 | 만료 시각을 Unix 초로 나타낸 값이다. |

기본 제공 발급 도우미는 HMAC-SHA-256 결과를 패딩 없는 base64url로 인코딩해 `sub`를 만든다. 키는 발급자의 비밀 문자열을 UTF-8로 인코딩한 값이다. 메시지는 `personId + "\u0000" + audience`를 UTF-8로 인코딩한 값이다. 구분자는 실제 NUL 문자다. 검증기는 서명된 주체 식별자 문자열을 그대로 쓰고 이 값을 다시 계산하지 않는다.

`issuePersonAttestation`은 `idpKey`, `idpIssuer`, `secret`, `personId`, `audience`, `principalPublicKey`, `durationSec`를 받는다. 대상은 직렬화된 오리진이어야 한다. 기간은 0 이상의 유한한 수여야 한다. 발급 도우미는 `now`가 있으면 그 값으로, 없으면 현재 시각으로 `iat`를 설정한다. `exp`는 `iat + floor(durationSec)`로 설정한다.

`issueMandate`에 `personAttestation`을 넘기면 발급 도우미는 앞뒤 공백을 없앤 뒤 서명 검증 없이 `sub`와 `exp`를 읽고 사람 보증서를 `pa`에 넣는다. 사람 보증서가 조각보다 먼저 만료되면 발급에 실패한다. 사이트는 요청을 받을 때 사람 보증서를 따로 검증한다.

`personIssuers`는 `{ iss, jwks }` 항목의 배열로 설정한다. 검증기는 `iss`가 같은 항목들의 키 목록을 합친다. 사용할 수 있는 키 가운데 썸프린트가 `kid`와 일치하는 첫 키를 쓴다. 발급자 식별자 하나에 키를 여러 개 등록해 두면 키를 교체할 수 있다.

사람 보증서가 있으면 검증기는 형식, 설정된 발급자와 키, 서명, 대상, 시각, 위임장과 연결되는지를 반드시 검사한다. 사람 보증서는 반드시 `iat <= exp`를 만족한다. 사람 보증서의 `exp`는 위임장의 `exp`보다 일러서는 안 된다. 검증 시각이 `iat - clockSkewSec`나 `exp + clockSkewSec`일 때도 시간 검사를 통과한다. 위임장의 `iss`는 사람 보증서의 `cnf.jwk`에서 구한 썸프린트 URI여야 한다. 위임장의 `sub`는 사람 보증서의 `sub`와 같아야 한다.

## 5. 요청 서명

에이전트는 자신의 Ed25519 개인 키로 서명하고 그 서명에 맞는 RFC 9421 `Signature-Input`과 `Signature` 필드를 보낸다. 검증기는 서명 입력을 하나만 받고 위임장의 `cnf.jwk`에 담긴 공개 키로 서명을 검증한다.

서명에 다음 구성 요소를 반드시 포함한다. 구성 요소 매개변수는 붙이지 않는다.

| 적용 대상 | 필수 구성 요소 |
| --- | --- |
| 모든 요청 | `@method`, `@authority`, `@path`, `@query`, `agent-mandate` |
| 본문이 있는 요청 | 위 구성 요소 전부와 `content-digest` |

Fetch의 `Request.body`가 null이 아니면 본문이 있는 요청으로 본다. 바이트가 하나도 없는 스트림도 여기에 해당한다. `Content-Digest` 필드 값은 반드시 `sha-256=:<digest>:`와 같다. `<digest>`는 본문 바이트의 SHA-256 해시를 표준 base64로 인코딩한 값이다. 검증기는 필드 값이 정확히 일치하는지 확인한다. 본문이 null인 요청에는 다이제스트 필드를 요구하지 않고 다이제스트 검사도 하지 않는다.

| 서명 매개변수 | 값 |
| --- | --- |
| `tag` | `web-bot-auth` |
| `keyid` | 에이전트 키의 썸프린트다. |
| `created`, `expires` | Unix 초로 나타낸 시각이다. `created <= expires`와 `expires - created <= 300`을 만족해야 한다. 서명자는 `expires = created + 300`으로 설정한다. |
| `nonce` | 64바이트를 표준 base64 또는 패딩 없는 base64url로 인코딩한 정규 표현이다. 서명자는 요청마다 무작위 64바이트를 새로 만들어 표준 base64로 인코딩한다. |
| `alg` | 서명자는 `ed25519`를 넣는다. 검증기는 위임장의 Ed25519 키를 사용한다. |

검증기는 서명 파싱, 서명의 경과 시간과 만료 검사, nonce 구문 검사를 `web-bot-auth`에 맡긴다. 이때 검증기의 시각, 허용하는 최대 경과 시간인 300초, `clockSkewSec`를 넘긴다. 태그, 필수 구성 요소, 서명 유효 기간의 300초 제한은 검증기가 직접 검사한다.

## 6. 검증

`verifyRequest(request, config, route, store, now?)`는 검증 결과를 담는 Promise를 반환한다. 위임장, 사람 보증서, nonce TTL의 시각 계산에는 `nowSec = floor(now.getTime() / 1000)`을 쓴다. `now`의 기본값은 현재 시각이다. 저장소 작업에 쓰는 시계는 8절에서 설명한다.

### 설정

| 설정 | 기본값 | 유형과 규칙 |
| --- | --- | --- |
| `origin` | 필수 | 직렬화된 HTTP 또는 HTTPS 오리진이다. |
| `maxLifetimeSec` | 86400 | 1 이상 2592000 이하의 정수다. `exp - nbf`의 상한이다. |
| `clockSkewSec` | 30 | 0 이상 300 이하의 정수다. |
| `maxTaskSec` | 2592000 | 1 이상 2592000 이하의 정수다. `(tend ?? exp) - (tbeg ?? iat)`의 상한이다. |
| `maxBodyBytes` | 1048576 | 1 이상의 정수다. 명시된 상한은 없다. |
| `trustedIssuers` | 빈 배열 | 허용할 위임장 발급자 문자열의 목록이다. 빈 목록이면 이 검사에서는 유효한 자체 발급 위임장을 모두 허용한다. |
| `onNoMandate` | `"challenge"` | `"challenge"` 또는 `"deny"`다. |
| `personIssuers` | 빈 배열 | 신뢰하는 사람 보증서 발급자의 식별자와 JWK 목록이다. |
| `requirePerson` | `false` | 불리언이다. true면 `personIssuers` 목록에 항목이 있어야 한다. |
| `onePerPerson` | `false` | 불리언이다. true면 `requirePerson`도 true여야 한다. 이때 사람 보증서 발급자 식별자는 모두 같아야 한다. |
| `minSwitchSec` | 600 | 1 이상의 유한한 수다. 소수도 허용한다. 명시된 상한은 없다. |

검증기는 요청을 살펴보기 전에 설정을 검증한다. 위 표에 나온 수의 범위, 오리진의 직렬화 형식, 사람 보증서 발급자 설정의 조건을 검사한다. 경로 정책에 `requireTask: { type, resource? }`를 지정할 수 있다.

### 검사 순서

다음 순서로 검사한다. 사유 코드는 처음 실패한 검사의 것을 쓴다. 결과는 `NO_MANDATE`이면 `onNoMandate` 값이고, 나머지 실패에서는 `deny`다.

| 순서 | 실패 조건 | 사유 코드 |
| --- | --- | --- |
| 1 | `Agent-Mandate` 헤더가 없다. 헤더 값이 비어 있으면 위임장 파싱으로 넘어간다. | `NO_MANDATE` |
| 2 | 명시한 `Content-Length`가 `maxBodyBytes`를 초과하거나 값이 유효하지 않다. | `BODY_TOO_LARGE` |
| 3 | 위임장 파싱, 크기, 헤더의 `typ`, 클레임 구조, 클레임 값, 시각 순서 중 하나라도 검사에 실패한다. 에이전트 JWK가 유효하지 않거나 필수인 `tbeg`가 없는 경우도 포함한다. | `MANDATE_MALFORMED` |
| 4 | 위임장에 본인의 JWK가 없거나 그 키가 유효하지 않다. 그 키의 썸프린트 URI가 `iss`와 다르거나, `alg`가 `EdDSA`와 다르거나, 위임장 서명이 유효하지 않은 경우도 포함한다. | `MANDATE_SIG_INVALID` |
| 5 | `trustedIssuers`에 항목이 있지만 위임장의 `iss`가 그 목록에 없다. | `ISSUER_NOT_TRUSTED` |
| 6 | `requirePerson`이 true이고 `pa`가 없다. | `PERSON_REQUIRED` |
| 7 | `pa`가 있으나 4절의 검사 중 하나라도 통과하지 못한다. | `PERSON_INVALID` |
| 8 | 위임장의 `aud` 또는 요청 URL의 직렬화된 오리진이 `config.origin`과 다르다. | `AUD_MISMATCH` |
| 9 | `nowSec < nbf - clockSkewSec` 또는 `iat > nowSec + clockSkewSec`다. | `NOT_YET_VALID` |
| 10 | `nowSec >= exp + clockSkewSec` 또는 `nowSec >= (tend ?? exp) + clockSkewSec`다. | `EXPIRED` |
| 11 | `exp - nbf > maxLifetimeSec` 또는 `(tend ?? exp) - (tbeg ?? iat) > maxTaskSec`다. | `LIFETIME_TOO_LONG` |
| 12 | `Signature`와 `Signature-Input`이 둘 다 없다. | `SIG_MISSING` |
| 13 | 두 서명 필드 중 하나만 있다. 서명 입력의 단일 구조화 필드 멤버에서 키 ID를 얻을 수 없는 경우도 포함한다. | `SIG_INVALID` |
| 14 | `keyid`가 있는데 위임장에 명시된 에이전트 키의 썸프린트와 다르다. | `KEY_MISMATCH` |
| 15 | HTTP 메시지 서명 검증에 실패하거나 태그가 올바르지 않다. 매개변수 없이 서명에 포함해야 할 구성 요소가 빠진 경우도 포함한다. | `SIG_INVALID` |
| 16 | 스트림으로 읽은 본문이 `maxBodyBytes`를 초과한다. | `BODY_TOO_LARGE` |
| 17 | 다이제스트 검사에 실패하거나, 서명 유효 기간이 유한하지 않거나 300초를 초과하거나, nonce가 유효하지 않다. | `SIG_INVALID` |
| 18 | nonce를 예약할 때 저장소가 `false`를 반환한다. | `REPLAY` |
| 19 | `requireTask`를 설정했는데 `task.type`이 다르거나, `requireTask.resource`를 설정했는데 `task.resource`가 다르다. | `TASK_NOT_ALLOWED` |
| 20 | 행동 횟수를 세는 요청에서 TTL이 1초 미만이다. | `EXPIRED` |
| 21 | 행동 횟수를 세는 요청에서 `consumeAction`이 `false`를 반환한다. | `LIMIT_EXCEEDED` |
| 22 | 사람 칸을 확보해야 하는 요청에서 `claimPersonSlot`이 `"superseded"`를 반환한다. 21단계에서 집계한 행동을 되돌린다. | `SUPERSEDED` |

본문을 읽기 전에 `Content-Length` 값의 앞뒤 공백을 제거한다. 남은 값이 십진 숫자로만 이루어져 있고 음이 아닌 안전한 정수를 나타내면 허용한다. 그 밖의 값은 상한을 초과한 것으로 본다. 명시한 길이가 상한 이하여도 검증기는 실제 본문 바이트 수를 확인한다. 검증기는 본문 복제본을 읽다가 다음 조각을 더하면 상한을 넘는 시점에 읽기를 멈추고 그 조각은 버린다. 애플리케이션은 요청 본문을 계속 사용할 수 있다.

nonce 예약의 키는 서명의 nonce 문자열이다. TTL은 `max(floor(signatureExpiresMs / 1000) - nowSec + clockSkewSec, 1)`초다. nonce 예약은 과업 일치 확인, 행동 횟수 집계, 사람 칸 확보보다 먼저 한다. 나중에 요청을 거부하거나 행동 횟수를 되돌려도 nonce 예약은 만료될 때까지 유지한다.

### 검증 결과와 되돌리기

허용이 아닌 검증 결과는 `{ decision: "challenge" | "deny", code: ReasonCode }`다. 허용 결과에는 `decision: "allow"`와 다음 필드가 있다.

| 필드 | 값 |
| --- | --- |
| `principal` | 위임장의 `sub`다. |
| `agentKeyId` | 위임장에 담긴 `cnf.jwk`의 썸프린트다. |
| `mandateId` | 위임장의 `jti`다. |
| `taskId` | 위임장의 `tid`다. 생략된 경우 `jti`를 쓴다. |
| `task` | 검사를 통과한 과업 객체다. |
| `person` | 사람 보증서 검증에 성공하면 들어간다. 사람 보증서의 `iss`와 `sub`를 담으며, 두 값을 함께 써서 보증받은 주체를 식별한다. |
| `refund()` | 행동 횟수에서 한 번을 되돌리는 비동기 콜백이다. |

검증 과정에서 행동 횟수를 늘렸으나 실제 행동이 없었으면 `refund()`를 호출한다. `refund()`는 허용 결과 하나당 행동 횟수를 최대 한 번 줄이며, 집계한 행동이 없으면 아무 일도 하지 않는다. 두 번째 호출은 앞서 실패한 되돌리기를 재시도하지 않는다. nonce 예약과 사람 칸은 그대로 유지한다.

`@task-mandate/hono`의 `taskMandate` 미들웨어에서 저장소는 필수 인수이고 `now: () => Date`는 선택 인수다. 보호할 경로마다 경로 정책을 지정할 수 있다. 허용 결과는 `c.get("mandate")`로 가져올 수 있다. 허용이 아닌 결과는 JSON으로 반환하며, 상태 코드는 `challenge`면 401, `deny`면 403이다. 후속 응답의 상태 코드가 200 이상 299 이하를 벗어나거나 후속 핸들러가 예외를 던지면 행동 횟수를 되돌린다. 되돌리기에 성공하면 핸들러의 예외를 다시 던진다.

## 7. 행동 횟수 집계와 사람별 제한

### 행동 횟수 카운터

경로에 `requireTask`를 지정했고 위임장에 `limits`가 있으면 카운터를 적용한다. 카운터의 키는 `iss + "\u0000" + aud + "\u0000" + (tid ?? jti)`다. 구분자로 실제 NUL 문자를 쓴다. 과업이 끝날 때까지 횟수를 유지하려면 같은 과업의 조각에 공통 `tid`와 `tend`를 설정한다.

저장소에 전달하는 TTL은 `(tend ?? exp) + clockSkewSec - nowSec`초다. 저장소 시계로 `expiresAt <= now`이면 그 행은 만료된 것으로 본다. `consumeAction`을 한 번 호출해 횟수를 주어진 `maxActions`와 비교하고 원자적으로 늘린다. 횟수를 늘리지 못해도 만료되지 않은 카운터라면 만료 시각은 연장할 수 있다. 이때 횟수는 그대로다. 되돌리기는 만료되지 않은 카운터의 양수 횟수를 하나 줄인다. 줄인 뒤에도 횟수가 양수이면 기존 만료 시각을 유지한다.

### 사람 칸

`onePerPerson`을 사용하면 사람 칸 검사에 도달한 모든 요청은 사람 칸을 확보해야 한다. `requireTask`가 없는 경로도 마찬가지다. 확보 요청에는 다음 필드를 사용한다.

| 필드 | 값 |
| --- | --- |
| `personKey` | 사람 보증서의 `iss + "\u0000" + sub`다. 구분자로 실제 NUL 문자를 쓴다. |
| `taskKey` | 행동 횟수 카운터의 키다. 경로에서 행동 횟수를 세지 않아도 이 키를 사용한다. |
| `agentKeyId` | 에이전트 키의 썸프린트다. |
| `taskBegin` | `tbeg ?? iat`를 Unix 초로 나타낸 값이다. |
| `expiresAt` | `(tend ?? exp) + clockSkewSec`를 Unix 초로 나타낸 값이다. |
| `now` | `nowSec`를 Unix 초로 나타낸 값이다. |
| `minSwitchSec` | 설정된 최소 간격을 초로 나타낸 값이다. |

저장소는 사람 키마다 현재 사람 칸 하나와, 그 칸에서 밀려난 과업과 에이전트 쌍의 목록을 보관한다. 현재 사람 칸에는 그 쌍과 `taskBegin`, `claimedAt`, `expiresAt`을 기록한다. 밀려난 쌍에는 각각 기존 만료 시각을 함께 보관한다. 먼저 `expiresAt <= now`인 항목을 버린 다음, 처음 일치하는 규칙을 적용한다.

| 순서 | 조건 | 결과와 변경 사항 |
| --- | --- | --- |
| 1 | 요청의 `(taskKey, agentKeyId)`가 밀려난 쌍 중 아직 만료되지 않은 것과 일치한다. | `"superseded"`다. |
| 2 | 만료되지 않은 현재 사람 칸이 없다. | `"ok"`다. 요청에 담긴 값과 `claimedAt = now`로 사람 칸을 만든다. |
| 3 | 요청의 쌍과 `taskBegin`이 현재 사람 칸의 값과 일치한다. | `"ok"`다. 현재 만료 시각과 요청의 만료 시각 중 더 늦은 값을 적용한다. `claimedAt`은 유지한다. |
| 4 | 요청의 쌍이 현재 쌍과 다르고, 요청의 `taskBegin`이 더 늦으며, `now - claimedAt >= minSwitchSec`를 만족한다. | `"ok"`다. 현재 쌍을 기존 만료 시각과 함께 밀려난 쌍의 목록으로 옮긴다. 요청의 쌍으로 새 사람 칸을 만든다. `claimedAt = now`를 기록하고 두 만료 시각 중 더 늦은 값을 적용한다. |
| 5 | 나머지 모든 확보 요청이다. | `"superseded"`다. |

시작 시각이 같은 두 과업은 현재 사람 칸이 만료되기 전까지 서로를 밀어낼 수 없다. 시작 시각만 바꿔서는 만료되지 않은 사람 칸을 교체할 수 없다. 에이전트 키를 바꾸면 다른 쌍이 된다.

행동 횟수는 반드시 사람 칸을 확보하기 전에 집계한다. 횟수 한도에 도달하면 사람 칸은 건드리지 않는다. 확보 요청이 거부되면 그 요청에서 집계한 행동을 되돌린다. 나중에 애플리케이션 오류가 나거나 행동 횟수를 되돌리더라도 이미 확보한 사람 칸은 그대로 유지한다.

## 8. 저장소 인터페이스

| 메서드 | 원자적 동작 |
| --- | --- |
| `claimNonce(nonce, ttlSec): Promise<boolean>` | 만료되지 않은 nonce면 `false`를 반환한다. 그렇지 않으면 TTL 동안 nonce를 기록하고 `true`를 반환한다. |
| `consumeAction(key, max, ttlSec): Promise<boolean>` | `ttlSec < 1`이면 횟수를 늘리지 않고 `false`를 반환한다. 만료된 행은 없는 것으로 처리한다. 만료되지 않은 횟수가 `max` 미만이면 횟수를 하나 늘리고 `true`를 반환한다. TTL이 유효하면 TTL로 새 만료 시각을 계산한다. 만료되지 않은 행이 있으면 기존 값과 새 값 중 더 늦은 값을 쓴다. 한도에 도달한 상태에서 호출해도 만료 시각을 연장할 수 있다. |
| `refundAction(key): Promise<void>` | 만료되지 않은 양수 횟수를 하나 줄인다. 횟수가 없거나 만료됐거나 0이면 그대로 둔다. 기본 제공 저장소는 횟수가 0이 되면 행을 삭제한다. |
| `claimPersonSlot(input): Promise<"ok" \| "superseded">` | 해당 사람의 만료된 항목 삭제와 사람 칸 규칙 적용을 한 연산으로 처리한다. 입력 필드는 7절에 있다. |

각 메서드는 여러 호출자가 동시에 호출해도 반드시 원자적으로 동작한다. 서로 다른 저장소 핸들로 호출할 때도 마찬가지다. 같은 사이트의 모든 검증기 인스턴스는 저장소 네임스페이스를 공유한다. 백엔드는 원자적 갱신을 지원하거나 관련 읽기와 쓰기를 직렬화할 방법을 제공해야 한다.

nonce와 행동 횟수의 TTL은 저장소 시계를 기준으로 하며 초 단위로 전달한다. 기본 제공 저장소는 밀리초 단위의 저장소 시각에 `ttlSec * 1000`을 더해 nonce의 만료 시각을 기록한다. 행동 횟수의 만료 시각은 저장소 시각에서 초 미만을 버린 뒤 `ttlSec`를 더해 계산한다. 두 경우 모두 현재 시각이 만료 시각에 도달하면 만료로 처리한다. 사람 칸 확보에는 `input.now`로 전달한 검증기 시각을 사용한다. 검증기와 저장소의 시계는 맞춘다. 확보 요청과 별개로 사람 상태에서 만료된 항목을 정리할 때도 시계를 맞춘다.

`memoryStore({ now? })`는 현재 프로세스 안에서만 동작한다. 선택 인자인 시계는 nonce와 행동 횟수의 만료 판단, `size()`의 정리 작업에 쓰인다. 기본 시계는 현재 시각을 사용한다. `size()`는 개수를 `{ nonces, actions, people }` 형식으로 반환한다. 기본 제공 메모리 저장소와 Worker 저장소는 nonce, 행동 횟수, 사람, 사람 칸의 과업에 해당하는 키를 SHA-256으로 해시해 16진수로 저장한다.

`@task-mandate/store-conformance`는 Vitest용 `defineStoreConformance(name, makeStore, options?)`를 내보낸다. 팩터리는 시험 사례마다 새 저장소를 반환한다. 시험 모음은 재전송, TTL 경계, 행동 횟수 집계, 되돌리기, 사람 칸 규칙, 동시 호출을 검사한다. `options.now`로 시험용 시계를 제공한다. 선택 함수 `advance(ms)`가 있으면 기다리지 않고 시계를 앞당길 수 있다. `options.makePair`를 주면 공유 상태 시험이 추가된다. 같은 저장소의 핸들 두 개로 행동 횟수 집계와 nonce 예약을 동시에 호출하는 시험이다.

## 9. 갱신과 철회

`LeasePlan`은 `taskId`, `start`, `end`, `chunkSec`를 담는다. 다음 조각에는 새 `jti`를 발급한다. 과업 ID, 과업 시작 시각과 종료 시각, 대상, 키는 재사용한다. `issueMandate`에 `taskId`, `taskBegin: plan.start`, `taskEnd: plan.end`를 전달한다. 과업이 길면 후속 조각을 발급할 때 새 사람 보증서가 필요할 수 있다.

`nextRenewal(plan, now, current, stopped)`에는 1 이상의 유한한 `chunkSec`와 유효한 날짜 값이 필요하다. `end > start`를 만족해야 한다. `current`가 있으면 `nbf`와 `exp`를 담는다. 입력을 검사한 뒤 처음 일치하는 규칙을 적용한다.

| 조건 | 결과 |
| --- | --- |
| `stopped`가 true다. | `stopped` |
| `now >= end`다. | `finished` |
| `now < start`다. | `not-started` |
| 현재 조각이 없거나 남은 시간이 초 단위로 `chunkSec / 2` 이하다. | `nbf = now`와 `exp = min(now + chunkSec, end)`로 발급한다. 기간은 초 단위로 더한다. |
| 그 외의 경우다. | `waiting` |

`Renewer`는 `tick()` 호출을 직렬로 처리한다. 계획과 `issue({ nbf, exp })`, `write(mandate)` 콜백을 받는다. 시계와 시작 조각은 선택 사항이다. 발급과 쓰기에 모두 성공하면 `issued`를 반환한다. `current()`로 토큰을 가져올 수 있다. `stop()`을 호출하면 이후 발급이 중단된다. 쓰기를 시작하기 전에 중단하면 발급 결과를 버린다. 이미 시작한 쓰기는 완료될 수 있다. 실행 일정은 호출자가 정한다. 만료 시각의 상한을 지키려면 계획에서 반환한 구간에 맞춰 토큰을 발급해야 한다.

갱신을 중단한 뒤에도 마지막으로 발급한 조각은 사이트의 만료 검사를 통과하는 동안 쓸 수 있다. 같은 시계를 기준으로 갱신을 중단한 때부터 만료 검사에서 실패할 때까지 최대 `chunkSec + clockSkewSec`가 걸린다. CLI의 기본 조각 길이 600초와 검증기의 기본 시계 오차 허용치 30초를 적용하면 최대 630초다. 이 상한은 새 검증 결과에 적용한다. 이미 허용한 작업은 중단하지 않는다. 위임장이나 사람 보증서의 철회 여부를 온라인으로 확인하는 절차는 없다.

`@task-mandate/cli`의 `tm` CLI는 `keygen`, `issue`, `inspect`, `delegate`, `run`, `list`, `stop`과 `idp`의 모의 발급자 명령을 지원한다. `keygen`은 개인 JWK를 파일에 쓰고, 같은 디렉터리에 `.pub.json` 파일도 쓴다. `inspect`는 위임장 구조와 서명이 검사를 통과하는지 알려 준다. 남은 시간도 표시한다.

`delegate`는 첫 조각을 발급하고 과업 상태를 `TM_HOME` 아래에 저장한다. 기본값은 `~/.task-mandate`다. `run`은 기본적으로 30초마다 갱신할지 확인한다. 사람 보증서 파일을 설정했으면 발급할 때마다 다시 읽는다. 출력 파일은 이름을 바꾸는 방식으로 교체하고, 그다음 상태 기록을 갱신한다. `stop`은 중단 표식을 기록한 뒤 과업 락을 기다린다. 이어 출력된 위임장의 만료 시각을 읽어 표시한다. 표시하는 값은 검증기의 시계 오차 허용치를 더하기 전의 `exp`이며 형식은 ISO 8601이다.

## 10. 에이전트 동작

`@task-mandate/agent`는 `mandatedFetch`와 `signRequest`를 내보낸다. 두 함수 모두 위임장 문자열이나 그 문자열을 반환하는 함수를 받는다. 위임장을 반환하는 함수는 동기 함수든 비동기 함수든 쓸 수 있다. 호출마다 위임장 값을 한 번 읽고 앞뒤 공백을 제거한다. 값이 없거나 비어 있으면 거부한다.

`mandatedFetch(input, init, options)`는 문자열 또는 URL을 받는다. 요청을 보내기 전에 위임장 구조와 발급자 서명을 검사하고, `aud`와 요청 URL의 오리진을 비교한다. `floor(nowMs / 1000) >= exp + 30`이면 요청을 보내지 않는다. 이 경계는 기본 시계 오차 허용치를 쓰는 검증기와 같다. 에이전트는 사이트의 신뢰 설정, 사람 보증서, 경로, 시작 시각, 상태 정책을 검사하지 않는다. 요청에는 `redirect: "manual"`을 사용한다.

`signRequest(request, options)`는 위임장 클레임, 대상, 만료 시각, 키 연결을 검증하지 않은 채 서명한다. 위임장 헤더를 교체하고, 본문이 있으면 다이제스트를 새로 계산한다. 기본 설정에서는 2097152바이트를 초과하는 본문을 거부한다. 본문을 읽다가 다음 조각을 더하면 상한을 넘는 시점에 읽기를 멈춘다. 선택 설정 `maxBodyBytes`로 서명 시 상한을 바꿀 수 있다. `mandatedFetch`는 서명할 때 기본 상한을 사용한다.

## 11. 오류 모델

`TaskMandateError`는 `Error`를 확장하며 `code`와 영어 메시지를 제공한다. 다음 코드는 호출자 오류를 나타낸다. 검증에 실패하면 6절의 사유 코드 중 하나를 담은 검증 결과를 반환한다.

| 코드 | 뜻 |
| --- | --- |
| `CONFIG_INVALID` | 검증기 또는 미들웨어 설정이 유효하지 않다. |
| `INPUT_INVALID` | 발급, 갱신, 에이전트 검사에서 호출자 입력이 유효하지 않음을 확인했다. |
| `KEY_INVALID` | JWK가 라이브러리의 Ed25519 키 구조 검사를 통과하지 못했다. |
| `STORE_REQUIRED` | 저장소를 지정하지 않고 Hono 미들웨어를 설정했다. |

저장소, 입출력, WebCrypto 키 가져오기, Fetch, 호출자가 넘긴 콜백에서도 오류가 날 수 있다. 이때 Promise는 해당 오류로 거부될 수 있다. 호출자는 거부된 Promise를 검증 결과와 별도로 처리해야 한다.

## 12. 보안 고려 사항

- 위임장 서명으로는 본인 키를 제어한다는 사실을, HTTP 메시지 서명으로는 지정된 에이전트 키를 제어한다는 사실을 확인할 수 있다. 유효한 서명만으로는 사이트가 실제 신원을 확인할 수 없다. 사이트는 `trustedIssuers`로 알려진 본인 키만 허용할 수 있다. `requirePerson`으로 사람 보증서 발급자가 주체 식별자와 본인 키의 연결을 보증하도록 요구할 수도 있다.
- 사람 보증서 발급자는 자신이 관리하는 주체 식별자를 어떤 본인 키에든 연결할 수 있다. 이미 사용 중인 주체 식별자도 마찬가지다. 그 경우 사람 칸 규칙에 따라 기존 쌍이 밀려날 수 있다. 이 연결의 안전성은 발급자의 신원 확인과 키 관리에 달려 있다.
- 요청 서명은 필수 구성 요소와 본문 바이트의 다이제스트를 보호한다. 다른 헤더는 서명에 포함한 경우에만 보호한다. 전송 중 자격 증명과 콘텐츠를 보호하려면 HTTPS를 사용한다.
- 재전송 방지는 같은 저장소에서 만료되지 않은 nonce를 두 번째로 예약하려는 요청을 거부한다. 행동 한도는 행동 횟수를 세는 경로와 해당 카운터 키에 적용한다. 사이트는 과업 매개변수의 의미를 비롯해 자체 경로 정책과 애플리케이션 정책을 정하고 적용해야 한다.
- 카운터는 요청과 함께 받은 위임장의 한도와 과업 종료 시각을 사용한다. 검증기는 조각 간 한도가 일치하는지 확인하지 않는다. 과업, 키, 사이트 전체를 아우르는 총한도도 적용하지 않는다. 사람 칸은 보증받은 주체별로 동시에 사용할 수 있는 과업과 에이전트의 쌍을 제한한다. 이미 허용한 요청은 중단하지 않는다.
- nonce 예약, 행동 횟수 증가, 사람 칸 확보, 애플리케이션 실행은 각각 별도 작업이다. 되돌리기는 행동 횟수 카운터에만 적용한다. 작업 사이에 예외가 나거나 프로세스에 장애가 생기면 앞서 기록한 상태가 남을 수 있다. 되돌리기는 키가 가리키는 현재 유효한 카운터에 적용한다. 행동별 영수증은 제공하지 않는다. 되돌리기가 늦어지는 사이 같은 키로 카운터가 다시 생기면 새 카운터의 횟수가 줄어들 수 있다.
- 프로토콜은 키 복구나 즉시 철회를 지원하지 않는다. 본인 또는 에이전트의 개인 키가 유출된 경우에도 보호 수단을 제공하지 않는다. 온라인 상태 확인이나 투명성 로그는 제공하지 않는다.
- 헤더와 본문의 크기 제한으로 요청마다 처리할 작업량 일부에 상한을 둔다. 전체 요청 빈도 제한, 요청 수락 제어, 저장소 용량 계획은 배포할 때 고려한다. 이 구현은 독립 보안 감사를 거치지 않았다.

## 13. 개인정보 보호 고려 사항

사람 보증서의 주체 식별자는 발급자의 비밀값, 사람 식별자, 사이트 오리진에 따라 달라진다. 입력이 같으면 같은 값이 나온다. 발급자는 계산에 사용한 오리진과 사람 식별자를 안다. 발급자의 비밀값을 바꾸면 주체 식별자가 바뀌고, 사이트가 기존 사람 칸을 식별하는 방식도 달라질 수 있다.

사이트는 위임장 클레임, `iss`에 담긴 본인 키의 썸프린트, `keyid`에 담긴 에이전트 키의 썸프린트를 볼 수 있다. 두 키 중 하나라도 여러 사이트에서 재사용하면 썸프린트로 사이트 간 활동을 연결할 수 있다. 사이트별 주체 식별자를 사용할 때는 사이트마다 본인 키와 에이전트 키를 따로 쓴다. 서명된 위임장 토큰에는 클레임이 평문으로 들어 있다.

## 14. 적합성

[vectors/](../vectors/)의 JSON 시험 데이터에는 허용 사례와 모든 사유 코드를 확인하는 사례가 들어 있다. 각 시험 데이터는 검증기 설정, 검증 시각, 경로 정책, 순서가 정해진 요청과 기대 결과의 쌍을 담는다. 시험에서는 데이터마다 새 저장소를 만들고, 같은 데이터의 각 단계는 그 저장소를 공유한다. 기대 결과에는 직렬화할 수 있는 검증 결과 필드가 들어 있다. `vectors/keys.json`에는 공개 시험 자료와 시험 전용 고정 개인 키가 들어 있다.

Node.js 22 이상과 pnpm을 사용해 저장소 루트에서 다음 명령을 실행한다.

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm test
pnpm test:worker
```

`pnpm test`는 시험 벡터와 메모리 저장소 시험을 포함한다. `pnpm test:worker`는 Durable Object 저장소 사례를 포함한 Worker 시험을 실행한다. `pnpm build && pnpm vectors`는 `scripts/gen-vectors.ts` 스크립트로 시험 데이터를 다시 생성하고 `vectors/`에 저장한다.
